# 第一轮非盲设计检查（不用于盲测得分）

日期：2026-11-24

本检查由已知原始问题报告的同一研究会话完成，**存在答案污染**。它只能检验测试材料是否包含可审查的设计线索、审查建议是否具有比例性，不能计算 Skill 的历史预测能力。

| Case | 非盲判断 | 关键前置发现 | 最小充分处理 | 不应做的事 |
|---|---|---|---|---|
| C01 | NOT_READY | 讨论阶段同意设计 != 写入文件后批准；设计与计划命名空间可能重叠 | 冻结前检查最终文档，分离计划文件路径，再交给执行流程 | 为这一问题创建新的多 Agent 审批平台 |
| C02 | NEEDS_DECISION | FR 未指定搜索服务的用户步骤，候选组件可能把不同操作误合并 | 标注用户步骤与数据行为，决定是否真的需要共享 UI | 默认实现两个完整搜索子系统 |
| C03 | NOT_READY | 缺少可比较的内存基线、测量负载和成功阈值 | 在规格中确定采样方式、环境、基线、目标、功能回归验收 | 添加未经需要的通用可观测平台 |

| C06 | NOT_READY | 绝对路径作为实体 ID 与文件移动和多版本需求直接冲突 | 将稳定媒体身份和文件资产/路径分离；给出关系约束 | 提前实现尚未采纳的云同步或复杂历史系统 |

## 非盲复核结果

1. 六个样本均具有可评价的目标、边界或流程信息，没有依赖实际产品代码。
2. 前置方法的五种有价值的审查触发器分别是：文件批准边界、用户任务语义、可比较验收、约束权威传递、稳定数据身份。
3. 清洁负面对照 C05 能用于检验“发现问题的压力”是否导致过度工程，但当前**没有审查模型的真实输出**。
4. 这些都是在知道历史答案后进行的回顾性判断。不能将“5 个问题样本都能解释”当作模型实际命中。
5. 本次没有比较 A/B 两组，也没有盲测、置信区间或成功率。正式有效性仍为 **UNVERIFIED**。

## 后续验收所需证据

在全新、无答案背景的上下文中，对每个样本保存 A/B 两组原始审查输出；在输出固定后解封 `answer-key.md`；逐案报告遗漏、错误阻断、无端扩张与成本。案例为历史源码概括或事后重建，必须按证据等级分别解释，不能混成真实历史回放成功率。
