# 预执行门禁审查结论 — C02「报价网站中的搜索」

**证据等级：RECONSTRUCTED（重构规格，未验证）**

---

## 1. 判定：**NEEDS_DECISION**

规格内部无矛盾，架构方向（"通用搜索组件对接所有数据源"）合理且规模可控，不存在需要推翻的整体方案。但存在 **3 项阻塞级决策缺失 + 验收不可判定**：按现有文字开工，Goal agent 必然要自行发明"来源集合""匹配规则""跨源对齐方式"——正是本门禁要拦截的行为。

**重新判定条件**：若用户无法给出下方"最小决策清单"的 D1–D4，应立即改判 **NOT_READY**（不允许 agent 以 mock/任意来源顶替）。

---

## 2. 审查发现

### F-1｜阻塞｜价格来源集合未定义、且未验证可用性
- **证据**：「搜索返回**所有价格来源**的匹配结果」；「一个通用搜索组件对接**所有数据源**」；`evidence_level: RECONSTRUCTED`（全文未列出任何具体来源）
- **自主执行失败模式**：agent 必须"发明"来源集合——要么只实现 1–2 个自造/桩适配器却对外宣称"覆盖所有来源"（静默缩窄范围，验收无法判定）；要么自行选择若干公开 API（发明需求、凭据、契约，且不可复现）。二者的失败都不可事后察觉，因为"所有来源"本身无基线。
- **最小修复**：列出确切来源清单（数量 + 标识 + 访问方式 + 是否需鉴权/速率限制 + 由谁确认），并声明本版验收数据是**真实接口**还是**固定种子数据集**（后者会显著改变"所有来源"的含义，必须显式写明）。

### F-2｜阻塞｜"关键词"与"匹配"无判定规则
- **证据**：FR-SEARCH 全文仅「用户输入关键词后…返回…匹配结果」
- **自主执行失败模式**：agent 在"零件号精确匹配 / 前缀 / 子串包含 / 模糊相似度阈值"中自行择一；这些选择直接决定各来源的查询参数形态与适配器契约，事后改动等于重做数据层。交付物外观合理但行为未定义。
- **最小修复**：一句话回答三问：①关键词是精确件号、自由文本描述，还是二者皆可？②各来源的匹配规则（精确/前缀/包含/模糊+阈值）？③结果是否需要排序或相关性排名？

### F-3｜阻塞｜零件身份 / 跨源对齐未定义（基础且难以逆转）
- **证据**：「产品也包含零件选择和供应商价格比较能力，但尚未提供这些能力在页面中的用户任务流程描述」；方案仅有「统一返回匹配候选」
- **自主执行失败模式**：各来源返回各自的件号与品名，若无统一零件标识，搜索结果要么**无法跨源对齐**（对"报价"场景基本不可用），要么 agent 自建一套归一化映射并硬编码进适配器（涉及存储、接口契约、后续比较逻辑，改动成本高）。
- **最小修复**：指定对齐口径，二选一即可：①**有**规范零件标识（制造商件号+品牌，或既有零件主数据）；②**无**——本版不做跨源合并，结果按来源分组呈现，不新建零件实体。第二条是合法的更小范围，不是缺陷。

### F-4｜高｜价格可比性语义未声明（币种/单位/MOQ/包装/税/交期）
- **证据**：产品定位为「零部件**报价**」，并存在「供应商价格比较」能力，但无字段规则
- **自主执行失败模式**：agent 默认"各来源同币种同单位"这一**规格中不存在的假设**而静默呈现；或反向地自行引入汇率换算/单位归一化（= 新增功能 + 引入汇率时效、口径等未定义业务规则）。
- **最小修复**：给出每来源字段映射规则，并显式声明本版**只原样展示 + 标注**币种/单位/包装/MOQ，不做换算与归一化（除非业务明确要求）。属"声明不做什么"，成本极低。

### F-5｜高｜部分失败与零结果的可观测行为未定义
- **证据**：方案仅描述正常路径「对接所有数据源，统一返回匹配候选」
- **自主执行失败模式**：单来源超时 → 整体报错 vs 降级返回部分结果（agent 自选，用户可见差异极大）；零匹配来源被静默丢弃，使"返回所有来源"这一承诺在无任何痕迹的情况下不成立。
- **最小修复**：二选一并写死：①部分失败降级——其余来源照常返回，结果区显式标注该来源不可用（推荐，符合"所有来源"承诺）；②整体失败——任一来源异常即整次搜索报错。并明确零匹配来源是否显示"无匹配"行。

### F-6｜高｜无可观测验收与失败判据
- **证据**：全文仅有 FR-SEARCH 一句，无验收章节- **自主执行失败模式**：完成判定退化为"搜索能出结果即完成"，无客观基线，Gate 无法核对。
- **最小修复**：给出 5–7 条"Done means"清单，例如：给定来源集合 S 与关键词 K，返回结果覆盖 S 中所有有匹配的来源且每条可溯源至来源标识；无关键词 → 不发起查询并给出提示；某来源异常 → 符合 F-5 政策；跨源重复呈现规则符合 F-3 口径。

### F-7｜中｜"匹配候选"不是用户可理解的结果，最小字段未定
- **证据**：「统一返回匹配候选」
- **自主执行失败模式**：agent 自拟 schema，或过度精简到缺零件标识（下游不可用）；也可能在范围外顺带设计价格比较列。
- **最小修复**：列出结果行最小字段：零件标识（供应商件号/名称）、价格、币种、单位、来源标识、可选（库存/交期，无则不列）。只定字段，不定页面布局。

### F-8｜中｜结果规模、排序与分页未定义
- **失败模式**：agent 任意截断（如 10 条）或返回无界列表；无稳定排序导致 UI 抖动与不可复现验收。
- **最小修复**：明确本版是否需要分页、每来源取数上限 N、排序依据（注意：在 F-4 未解决可比性前，**不得**按价格排序）。

### F-9｜中｜范围边界与冻结/审批权威未声明
- **证据**：「产品也包含零件选择和供应商价格比较能力，但尚未提供这些能力在页面中的用户任务流程描述」；「禁止默认增加新功能」
- **失败模式**：agent 发现选择/比较未定义后，或顺手做简化版比较面板（越界），或把它当作前置阻塞而停摆；也不清楚交付物边界是"组件+接口"还是"含页面/路由"，以及谁能批准变更来源集合或 schema。
- **最小修复**：写明：本版范围 = FR-SEARCH（含其最小 UI 与接口）；零件选择 UI、价格比较/看板 **不在范围**；依赖未定的规范零件标识与价格字段时，记为接口假设并**上报确认**，不自建界面。并指定来源集合/规范 schema 的变更审批人。

### F-10｜中｜`RECONSTRUCTED` 状态下，"用户行为"本身未经确认
- **证据**：标题标注「证据等级：RECONSTRUCTED」，且规格中用户任务流程描述缺失
- **失败模式**：agent 把重构出来的叙述当作已验证需求实现，错误被固化进 schema 与界面。
- **最小修复**：补一句用户任务描述即可（谁、在什么场景、输入什么、期望看到什么），成本最低、锚定作用最大的一条。

## 3. 阻塞项 vs. 实施期可由 agent 自行决定

**必须在开工前由用户/负责人拍板（阻塞）**
1. 来源集合与验收基线（F-1：具体来源、访问方式、真实接口 or 种子数据）
2. 关键词类型与匹配规则（F-2）
3. 零件身份/跨源对齐口径（F-3）
4. 价格可比性呈现规则与"不做换算"声明（F-4）
5. 部分失败与零结果策略（F-5）
6. 验收清单与范围/审批权威（F-6、F-9、F-10）

**属可逆实现细节，agent 可在实施中自行决定并记录**
组件/目录结构、字段命名与序列化格式、适配器内部实现与重试次数、日志与埋点字段、错误提示文案、UI 组件库与布局、测试框架与单测写法、每来源取数上限 N（只要接口预留且不改变用户可见承诺）、加载态与分页控件的具体形态。

判别原则：**只影响"实现怎么做"且改动成本低的 → agent 决定；影响"用户看到什么/什么算完成/数据身份"的 → 必须先决策。**

---

## 4. 本门禁必须拒绝的范围扩张

- ❌ 零件选择/搜索结果内"一键选定零件"流程（规格明确无流程描述）
- ❌ 价格比较看板、跨供应商比价排序、汇率换算与单位归一化引擎
- ❌ 搜索建议、拼写纠正、同义词扩展、语义/向量检索
- ❌ 搜索历史、收藏、导出报价单
- ❌ 用户账号、权限、租户（未在本规格出现）
- ❌ 供应商价格源的后台管理、爬虫/数据管道运维
- ❌ 搜索分析看板与运营指标体系
- ❌ 反向扩展"报价单""订单"等下游流程

原则：**只交付"关键词 → 各来源匹配结果"这一条用户可感知行为及其最小 UI/接口。**

---

## 5. 已经足够、不要再扩张的部分

- **总体架构方向已足够**：单一通用搜索组件 + 逐来源适配 + 统一结果模型。这是合理且无需重做的选择，不必引入独立搜索服务集群、事件驱动架构或向量库。
- **范围规模已足够**：一条 FR-SEARCH 可独立交付，不需要补写完整 PRD、领域模型文档或 UI 设计稿来开工——缺口是"决策"，不是"文档篇幅"。
- **"禁止默认增加新功能"这条约束本身有效**，应直接写入 Goal 的执行约束，并配以第 4 节的显式排除清单。
- **"统一返回匹配候选"的统一化意图是对的**，值得保留为 schema 方向；缺的只是 F-3/F-7 两项具体口径。

---

## 6. 最小决策清单（用户一次性回答即可解锁开工）

| # | 决策点 | 选项（建议项加粗） |
|---|---|---|
| D1 | 价格来源集合 | 列出具体来源清单；本版验收用 **固定种子数据集** 还是 **真实接口** |
| D2 | 关键词与匹配 | 精确件号 / 自由文本 / 皆可；各来源匹配规则；是否需要排序 |
| D3 | 跨源对齐 | 有规范零件标识（说明是什么）/ **无 —— 按来源分组，不做合并** |
| D4 | 价格呈现 | 原样展示并标注币种·单位·包装·MOQ，**不做换算与归一化** |
| D5 | 失败与空结果 | **部分失败降级 + 显式标注来源不可用** / 整体失败；零匹配来源是否显示 |
| D6 | 范围与审批 | 本版仅搜索，**排除**零件选择与价格比较；谁能批准变更来源集合与规范 schema |
| D7 | 用户任务一句话 | 谁在什么场景输入什么关键词、期望看到什么（用于确认 RECONSTRUCTED 内容） |

答完 D1–D7，本规格即可判 **READY**；其中 D1、D2、D3 任一缺失时应保持 **NOT_READY**，不允许 agent 以桩实现或自行假设推进。
