# 前置设计缺陷回放实验 — 第一批

**目的：**验证一个 Goal 启动前的规格审查方法，能否提前发现核心功能、规格传递、架构及验收等重大问题，同时抑制不必要的设计膨胀。

本批采用 6 个样本：1 个历史原始工作流快照、3 个由公开问题报告重建的早期需求、1 个假设性工程前瞻样本、1 个无重大缺陷的负面对照。

## 严格区分证据等级

- **HISTORICAL-SNAPSHOT：**冻结时间早于公开问题报告，使用原始历史源码片段。可用于后续真正的历史回放。
- **RECONSTRUCTED：**根据报告重建，无法证明文字与当时真实设计完全相同；仅用于机制覆盖测试。
- **SYNTHETIC：**人工构造，测试特定设计特性；不能证明历史预测能力。

**重要限制：**建立本测试集的本次会话已经知道问题答案，因此任何本会话的审查都只能标记 `retrospective`，不得登记 `blind`、命中率或真实预测成功率。

## 文件

- `cases/` — 只包含测试时提供给审查者的材料，不出现报告故障的 Issue 编号和预期答案。
- `reviewer-protocol.md` — 对照实验方法、输出格式和评分原则。
- `answer-key.md` — 源链接、标签和预期结果。仅由裁判在审查提交后阅读。
- `pilot-report.md` — 当前已经完成的检查与尚未执行的实验。

## 运行方式

1. 在独立的新上下文中，仅给受测模型 `cases/Cxx-*.md` 和相应审查指令。
2. 不提供本目录的 `README.md`、`answer-key.md`、`pilot-report.md`，也不提供本项目历史讨论。
3. A 组使用普通设计审查；B 组使用 `goal-spec` 候选审查规则。两个组采用相同模型、预算与材料。
4. 审查者必须输出可定位到输入文本的缺陷、影响、最小修复建议，并且允许明确给出“无阻断问题”。
5. 结果冻结后再由独立裁判根据 `answer-key.md` 核对；不允许事后修改问题定义或补充命中项。
6. 除命中之外同时记录虚假缺陷、无依据功能扩张、重大设计过度复杂化、人工决策数量与审查成本。

**验收：**真正的效果结论需要独立审查的实际输出；本批文件的存在不等于 Skill 有效。
