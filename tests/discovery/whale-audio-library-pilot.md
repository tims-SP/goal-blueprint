## D-01：文件内容身份与媒体记录归并

### 候选问题

当两个不同位置的文件内容完全相同时，系统应将它们视为两个独立媒体记录，还是同一个媒体记录的多个文件位置？

该问题影响内容去重、文件移动后的重新识别，以及媒体记录与物理文件位置之间的关系。

### 用户决策

**状态：Accepted（核心语义已确认）**

用户原始决策：

> Whale Audio Library 试运行 D-01 决策：每个文件就是独立媒体，移动文件时通过重新识别恢复关联。补充说明：无

随后针对完全相同内容的文件，用户明确选择：

> 内容完全相同就视为同一媒体记录，多个文件位置可以关联它。

### 当前确认的语义

1. 内容完全相同的文件归并为同一媒体记录。
2. 同一媒体记录可以关联多个文件位置。
3. 文件路径表达存储位置，不应单独充当稳定的媒体内容身份。
4. 文件移动后，需要通过重新识别恢复其与媒体记录的关联。
5. 本决策只确认完全相同内容的归并规则，不自动决定歌曲、专辑、录音版本等上层领域实体的关系。

### 历史设计兼容性核对

此前 Whale Audio Library 的历史讨论包含以下约束：

- 文件/媒体资产、曲库条目和设备路径分离。
- 完全相同的 `media_hash` 才归为同一 `media_asset`。
- 路径按设备保存，不应因路径变化覆盖媒体身份。

D-01 对“完全相同内容归并、多个位置关联”的确认，与上述 `media_hash` / `media_asset` 约束基本一致。

但这不代表用户已经确认了完整的 Asset、Track、Library Entry、Recording 或 Version 模型。历史讨论中的助手提案也不能自动视为用户批准的产品决策。

### 待验证边界

**D-01-U1：同一内容的多个位置是否需要独立管理？**

例如两个目录中存在内容完全相同的文件，用户是否需要分别删除其中一个位置、单独标记某个位置，或只对媒体记录执行统一操作？

当前用户决策只确认它们属于同一媒体记录，没有明确这些位置是否需要独立的生命周期或操作语义。

状态：Unverified

验证原则：只有当独立管理需求会影响产品行为、数据模型或删除语义时，才向用户提出具体决策；不要提前设计复杂的副本管理机制。

### 不得从 D-01 推导的结论

- 不得推导出所有不同编码、不同质量或不同录音版本都应合并。
- 不得推导出歌曲、专辑、录音、曲库条目必须合并为同一实体。
- 不得推导出路径、文件系统 ID、内容哈希中的某一种已经被确定为完整的移动识别实现。
- 不得将该决定视为对现有数据库结构或代码的修改授权。
